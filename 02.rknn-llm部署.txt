02.rknn-llm部署

一、模型转换

注意：迅为官方文档里的DeepSeek-R1-Distill-Qwen-1.5B会在rkllm 1.2.3 版本部署后出现回答无限重复的[PAD151935]的情况
可能原因
模型架构差异：不同架构对量化敏感度不同
激活值分布特性：DeepSeek模型可能有特殊的激活值分布，与rkllm 1.2.3的量化算法不兼容
校准数据适配性：Qwen3-1.7B的校准数据更符合RK3588的量化处理流程

因此以下换成Qwen3-1.7B模型，下方export代码里注意把deepseek的目录名称换成下载的qwen



Qwen3-1.7B 模型下载地址为：https://huggingface.co/Qwen/Qwen3-1.7B，
需要下载该网址全部的文件和模型
然后将上述文件全部拷贝到虚拟机 ubuntu；

然后将 “iTOP-3588 开发板\02_【iTOP-RK3588 开发板】开发资料\13_NPU 使用配套资料
\11_Deepseek 部署测试\01_rkllm-1.1.4\rknn-llm-main\examples\DeepSeek-R1-Distill-Qwen-1.5B_ Demo”路径下的文件拷贝同级目录：

拷贝完成如下，参考目录：
(rknn) wzp@ubuntu:~/RKNN/RKNN_test/qwen3-1.7b$ ls
deploy  export  Qwen3-1.7B


然后在终端中输入以下命令生成量化校准数据，过程如如下所示：
python3 generate_data_quant.py
python3 export_rkllm.py
(或者直接pycharm运行)

四、YOLO+LLM 联动：询问「摄像头看到了什么」
  你问 LLM，LLM 根据当前摄像头画面的 YOLO 检测结果回答。需要 YOLO 模型（.rknn）、LLM 模型（.rkllm）和本仓库中的 yolo_llm_camera 工程。yolo_llm_camera 使用与单独 YOLO 相同的线程池（默认 6 实例、3 核 NPU 并行），画面显示 FPS、延迟(ms)、检测数量与类别；终端约每秒打印 [Vision]；每次 LLM 回答结束后打印 Performance Metrics（时间、Token 数、速度、内存、CPU/NPU、温度）。

  1）编译（在 GITHUB 根目录下，且本机已配置 RKLLM_API_PATH）：
     cd yolo_llm_camera
     chmod +x build-linux.sh && ./build-linux.sh
     产物在 install/demo_Linux_aarch64/：yolo_llm_camera_demo 与 lib/、model/（若存在）。

  2）推送到开发板（路径可自定；以下用 GITHUB 与 qwen3-1.7b 的实际路径，请按本机修改）：
     adb shell mkdir -p /home/topeet/RKLLM/yolo_llm
     adb push /home/wzp/RKNN/RKNN_test/GITHUB/yolo_llm_camera/install/demo_Linux_aarch64/ /home/topeet/RKLLM/yolo_llm/
     adb push /home/wzp/RKNN/RKNN_test/qwen3-1.7b/export/Qwen3-1.7B_W8A8_RK3588.rkllm /home/topeet/RKLLM/yolo_llm/
     说明：推送后板上有 yolo_llm/demo_Linux_aarch64/（含 yolo_llm_camera_demo、lib、model）和 yolo_llm/Qwen3-1.7B_W8A8_RK3588.rkllm。若目录结构不同，请保证运行时可访问 ../Qwen3-1.7B_W8A8_RK3588.rkllm 与 model/RK3588/yolo26n.rknn。

  3）开发板运行（在 demo_Linux_aarch64 目录下执行；USB 摄像头一般为 /dev/video21，内置或 0 则用 0）：
     adb shell "cd /home/topeet/RKLLM/yolo_llm/demo_Linux_aarch64 && ulimit -HSn 102400 && export LD_LIBRARY_PATH=./lib && ./yolo_llm_camera_demo model/RK3588/yolo26n.rknn ../Qwen3-1.7B_W8A8_RK3588.rkllm /dev/video21 256 4096"

  4）运行后窗口持续显示 YOLO 画面，左上角有 FPS、Latency(ms)、objs+类别；终端约每秒打印 [Vision] N objs [...] FPS Latency。按 空格 或 回车 会直接用「摄像头看到了什么？」问 LLM 并输出回答（无需再输入）；每次 LLM 回答结束会打印 Performance Metrics。按 q 关闭窗口退出。


由于加载大语言模型会打开很多的文件，默认情况每个进程可以同时打开的文件数是有限
制的，所以需要在终端输入以下命令，允许当前用户在一个会话中打开最多 102400 个文件描述符。
ulimit -HSn 102400
然后使用以下命令，运行可执行程序，并加载 RKLLM 大语言模型，运行成功如所示：
export LD_LIBRARY_PATH=./lib
./llm_demo Qwen3-1.7B_W8A8_RK3588.rkllm 4096 4096



三、显示推理性能的参数

要在RK3588上查看 Token/s (Tokens per Second) 等性能数据，你主要是需要修改 C++ 推理代码（即你提供的第二部分代码）。Python代码主要是用于模型转换（构建）和量化数据的准备，真正的端侧性能主要在C++运行阶段体现。

运行build.sh
然后将编译得到的可执行文件拷贝到开发板上，在目录中同时存放：xxx.rkllm lib llm_demo
