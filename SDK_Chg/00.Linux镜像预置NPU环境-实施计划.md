# 开发板默认 RKNN 环境 — 实施计划

## 一、目标

- 烧录镜像后，开发板**默认就包含 RKNN 环境**，无需每次烧录都按 `01.rknn-toolkit2环境搭建.txt` 从头装 Miniconda、建 conda 环境、pip 装包、再推 so/server。
- 做法：在 SDK 里用最新 RKNN 运行时覆盖旧版，并把「Miniconda + rknn 环境 + librknnrt/rknn_server」预置进 rootfs（Ubuntu overlay），一次编镜像、烧录即用。

---

## 二、你原本在开发板上的配置流程（摘要）

依据 `01.rknn-toolkit2环境搭建.txt`，在**最原始开发板**上你是这样从零搭到可用 RKNN 的：

| 顺序 | 在开发板上做的（或本机推送到板子） |
|------|------------------------------------|
| 1 | 装 **Miniconda**：`wget` 下载 `Miniconda3-latest-Linux-aarch64.sh`，`chmod +x` 后执行安装（注意必须是 aarch64 版） |
| 2 | `source ~/.bashrc`，配置 **.condarc** 国内镜像源 |
| 3 | **创建 conda 环境**：`conda create -n rknn python=3.9 -y`，然后 `conda activate rknn` |
| 4 | `sudo apt-get update`，`sudo apt-get install -y cmake build-essential` |
| 5 | 本机用 **adb push** 把 `arm64_requirements_cp39.txt` 和 `rknn_toolkit2-2.3.2-...-aarch64.whl` 推到板子（如 `/home/topeet`） |
| 6 | 板子上 **pip 安装**：`pip install -r arm64_requirements_cp39.txt`，再 `pip install -U ...aarch64.whl`，最后 `pip install "opencv-python<=4.9.0.80"` |
| 7 | 用 **fix_rknn.sh**（或手动）：把 `librknnrt.so` 推到 `/usr/lib/`，`rknn_server` 推到 `/usr/bin/`，并执行一次 `rknn_server` |

目标就是：上面 1～7 步**都不用在板子上再做**，全部通过「更新 SDK + 预置进镜像」在烧录前完成。

---

## 三、更新 SDK 内 RKNN 为最新版本（必做）

和你在开发板上用 `fix_rknn.sh.txt` 时一样，**实际只需要 2 个文件**：板子上用的是 `/usr/lib/librknnrt.so` 和 `/usr/bin/rknn_server`，对应在 SDK 里先覆盖 aarch64 的这两个，后续编出来的镜像/overlay 才会是新版。

| 本机最新（复制源） | 覆盖到 SDK 的路径 |
|--------------------|--------------------|
| `rknn-toolkit2-2.3.2/rknpu2/runtime/Linux/librknn_api/aarch64/librknnrt.so` | `external/rknpu2/runtime/RK3588/Linux/librknn_api/aarch64/librknnrt.so` |
| `rknn-toolkit2-2.3.2/rknpu2/runtime/Linux/rknn_server/aarch64/usr/bin/rknn_server` | `external/rknpu2/runtime/RK3588/Linux/rknn_server/aarch64/usr/bin/rknn_server` |

**一键覆盖**（开发机执行，路径可按实际改）：

```bash
SRC=/home/wzp/RKNN/rknn-toolkit2-2.3.2/rknpu2/runtime/Linux
DST=/home/wzp/BSP/rk3588-linux/external/rknpu2/runtime/RK3588/Linux
cp -a "$SRC/librknn_api/aarch64/librknnrt.so" "$DST/librknn_api/aarch64/"
cp -a "$SRC/rknn_server/aarch64/usr/bin/rknn_server" "$DST/rknn_server/aarch64/usr/bin/"
```

**判断是否覆盖成功**：看目标文件大小、日期是否与源一致；或对比 md5。

```bash
# 方法一：看目标文件时间、大小（2.3.2 约为 7.7MB + 455KB，日期接近你本机包日期）
ls -l "$DST/librknn_api/aarch64/librknnrt.so" "$DST/rknn_server/aarch64/usr/bin/rknn_server"

# 方法二：源和目标逐项对比大小（两边字节数一致即成功）
ls -l "$SRC/librknn_api/aarch64/librknnrt.so" "$SRC/rknn_server/aarch64/usr/bin/rknn_server"
ls -l "$DST/librknn_api/aarch64/librknnrt.so" "$DST/rknn_server/aarch64/usr/bin/rknn_server"

# 方法三：md5 一致则内容完全一致
md5sum "$SRC/librknn_api/aarch64/librknnrt.so" "$DST/librknn_api/aarch64/librknnrt.so"
md5sum "$SRC/rknn_server/aarch64/usr/bin/rknn_server" "$DST/rknn_server/aarch64/usr/bin/rknn_server"
```

## 四、让镜像默认带 RKNN 环境（预置内容）

在完成第三节的 SDK 覆盖后，通过 **Ubuntu rootfs 的 overlay** 把下面内容做进镜像，烧录后板子就“默认有” RKNN 环境。

### 4.1 必预置（与 fix_rknn 一致）

| 镜像内路径 | 来源 |
|------------|------|
| `/usr/lib/librknnrt.so` | SDK 中已更新后的 `external/rknpu2/runtime/RK3588/Linux/librknn_api/aarch64/librknnrt.so` |
| `/usr/bin/rknn_server` | SDK 中已更新后的 `external/rknpu2/.../rknn_server/aarch64/usr/bin/rknn_server` |

拷贝到 `rk3588-linux/ubuntu/overlay/usr/lib/` 和 `ubuntu/overlay/usr/bin/` 即可。
```bash
# 在 SDK 根目录下执行
cd /home/wzp/BSP/rk3588-linux

sudo mkdir -p ubuntu/overlay/usr/lib ubuntu/overlay/usr/bin
sudo cp external/rknpu2/runtime/RK3588/Linux/librknn_api/aarch64/librknnrt.so ubuntu/overlay/usr/lib/
sudo cp external/rknpu2/runtime/RK3588/Linux/rknn_server/aarch64/usr/bin/rknn_server ubuntu/overlay/usr/bin/
sudo chmod +x ubuntu/overlay/usr/bin/rknn_server
```

### 4.2 预置 Miniconda + rknn 环境（通过 QEMU aarch64 挂载 rootfs 实操）

要在主机上模拟 ARM64 环境并把 Conda 装进去，可以用 QEMU + chroot 的方式，这样不用真的烧录到板子上就能把环境配好，最后打包成镜像。

**第一步：准备依赖和基础环境**
在你的开发机（x86 Ubuntu）上安装 qemu-user-static：
```bash
sudo apt-get update
sudo apt-get install -y qemu-user-static
```

**第二步：解压文件系统并挂载**
进入 SDK 的 ubuntu 目录，解压你想用的系统包（以 ubuntu20 为例），并挂载必要的系统目录：
```bash
# 先进入 SDK 的 ubuntu 目录！(重要)
cd /home/wzp/BSP/rk3588-linux/ubuntu

# 如果之前有 binary 目录，先删掉并重新创建
sudo rm -rf binary
mkdir binary

# 解压基础文件系统（这包解压出来自带一层 binary 目录，为防嵌套先解压到当前目录）
sudo tar -xf ubuntu-focal-xfce-arm64.tar.xz

# 将主机的 DNS 解析文件拷贝进去，保证里面能上网
sudo cp /etc/resolv.conf binary/etc/resolv.conf

# 拷贝 qemu-aarch64-static，这是跨架构运行的关键
sudo cp /usr/bin/qemu-aarch64-static binary/usr/bin/

# 挂载虚拟文件系统
sudo mount -t proc /proc binary/proc
sudo mount -t sysfs /sys binary/sys
sudo mount -o bind /dev binary/dev
sudo mount -o bind /dev/pts binary/dev/pts
```

**第三步：chroot 进入拟真环境**
由于是全新环境，我们可以直接在进入 chroot 之后用 `wget` 下载 Miniconda（就像你当初在开发板上做的一样），并把刚才覆盖给 SDK 的那份 2.3.2 安装包也先拷贝进 `binary/root/` 供里面使用。
```bash
# 从本机把 rknn_toolkit2/rkllm 最新的 aarch64/x86 包拷进拟真环境的 /root 下
sudo cp /home/wzp/RKNN/rknn-toolkit2-2.3.2/rknn-toolkit2/packages/arm64/arm64_requirements_cp39.txt binary/root/
sudo cp /home/wzp/RKNN/rknn-toolkit2-2.3.2/rknn-toolkit2/packages/arm64/rknn_toolkit2-2.3.2-cp39-cp39-manylinux_2_17_aarch64.manylinux2014_aarch64.whl binary/root/
sudo cp /home/wzp/RKNN/rknn-llm-main/rkllm-toolkit/packages/rkllm_toolkit-1.2.3-cp39-cp39-linux_x86_64.whl binary/root/

# chroot 进入系统（进入后终端会变成 root@ubuntu:/# ）
sudo chroot binary /bin/bash
```

**第四步：在拟真环境（ARM64）中按 `01` 文档搭建环境**
现在你已经在 ARM64 环境里了，可以完全按照你在开发板上的操作来：
```bash
# 1. 下载并安装 Miniconda
cd /root
wget -c https://mirrors.bfsu.edu.cn/anaconda/miniconda/Miniconda3-latest-Linux-aarch64.sh
chmod 777 Miniconda3-latest-Linux-aarch64.sh
./Miniconda3-latest-Linux-aarch64.sh -b -p /opt/miniconda3

# 2. 配置环境变量
echo 'export PATH="/opt/miniconda3/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

# 3. 配置 conda 镜像源并创建 rknn 环境
cat > ~/.condarc <<EOF
channels:
  - defaults
show_channel_urls: true
default_channels:
  - https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main
  - https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/r
  - https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/msys2
custom_channels:
  conda-forge: https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud
  pytorch: https://mirrors.tuna.tsinghua.edu.cn/anaconda/cloud
EOF

conda create -n rknn python=3.9 -y

# 4. 激活环境并安装系统依赖
# 注意：在 chroot 下直接 conda activate 可能失效，导致包被装到 base 环境。
# 必须使用 rknn 环境下绝对路径的 pip 才能确保包被正确安装！

apt-get update
# 非常重要：必须先安装 cmake 和 build-essential，否则 pip 安装 onnxoptimizer 会失败报错 "Could not find cmake executable"
apt-get install -y cmake build-essential

# 5. 用绝对路径的 pip 强制安装到 rknn 环境
/opt/miniconda3/envs/rknn/bin/pip install -r /root/arm64_requirements_cp39.txt -i https://mirrors.aliyun.com/pypi/simple/
/opt/miniconda3/envs/rknn/bin/pip install -U /root/rknn_toolkit2-2.3.2-cp39-cp39-manylinux_2_17_aarch64.manylinux2014_aarch64.whl -i https://mirrors.aliyun.com/pypi/simple/
/opt/miniconda3/envs/rknn/bin/pip install "opencv-python<=4.9.0.80" -i https://mirrors.aliyun.com/pypi/simple/
/opt/miniconda3/envs/rknn/bin/pip install /root/rkllm_toolkit-1.2.3-cp39-cp39-linux_x86_64.whl -i https://pypi.mirrors.tuna.tsinghua.edu.cn/simple

# 安装完成后，清理安装包减小体积
rm -rf /root/Miniconda*.sh /root/*.whl /root/*.txt
/opt/miniconda3/bin/conda clean --all -y
/opt/miniconda3/envs/rknn/bin/pip cache purge

# 退出 chroot
exit
```

**第五步：在拟真环境模拟开发板测试（可选但推荐）**
在退出 chroot 之前（或者在主机中重新 `sudo chroot binary /bin/bash` 进去后），你可以直接在当前的终端（`root@ubuntu:/#`）里模拟开发板开机，验证环境是否 100% 成功安装到了 rknn 里：
```bash
# 1. 模拟开发板登录，加载刚才配置好的环境变量脚本
source /etc/profile.d/rknn_env.sh
# 此时终端提示符前应该会出现 (rknn)

# 2. 检查包是否成功安装
pip show rknn-toolkit2
python -c "import cv2; print('OpenCV 版本:', cv2.__version__)"

# 3. 跑一段 Python 代码验证 RKNN API 能不能导入
python -c "from rknn.api import RKNN; print('RKNN 包导入成功！')"
# 注意：由于你在主机的 x86 环境模拟，没有真实 NPU 硬件，可能会报 /dev/rknpu 相关的硬件错，这是正常的，只要不报 ModuleNotFoundError 就是成功的。
```

**第六步：取消挂载并把环境做进 overlay**
```bash
# 确认没问题后，退出 chroot
exit

# 退出 chroot 后，取消挂载
sudo umount -lf binary/dev/pts 2> /dev/null || true
sudo umount -lf binary/* 2> /dev/null || true

# 此时 binary 目录里已经包含了你装好环境的完整 rootfs。
# 你可以直接把刚才装好的 /opt/miniconda3 提取到 SDK 的 overlay 里：
sudo mkdir -p overlay/opt
sudo cp -a binary/opt/miniconda3 overlay/opt/

# 让开发板开机所有用户都能默认加载 conda 并进入 rknn 环境
sudo mkdir -p overlay/etc/profile.d
sudo tee overlay/etc/profile.d/rknn_env.sh << 'EOF'
export PATH="/opt/miniconda3/bin:$PATH"
source /opt/miniconda3/bin/activate rknn
EOF
```

做完这些后，当你再次运行 `make ubuntu20` 编译 rootfs 时，`mk-rootfs.sh` 会自动把 `overlay` 里的内容压进镜像，烧录后开机就默认进 `rknn` 环境了。

### 4.3 建议一并预置

- **rknn_server 开机自启**：在 overlay 里加 systemd 服务（如 `etc/systemd/system/rknn-server.service`），内容与之前计划中的一致（`ExecStart=/usr/bin/rknn_server`），并做 `systemctl enable` 的链接。
- **ulimit**：若后续要跑 RKLLM，可在 overlay 的 `/etc/security/limits.d/99-rknn.conf` 或 `/etc/profile.d/rknn.sh` 里设 `ulimit -HSn 102400`，与 02 文档一致。

## 五、在 Docker 编译环境打包镜像（推荐）

为了避免主机环境升级带来的编译依赖问题，极力推荐在稳定的 Docker 环境中执行编译打包。这与 `02.Docker配置ubuntu20.04环境.txt` 的配置完美衔接。

由于我们在前面已经把需要预置的内容做进了 SDK 的 `ubuntu/overlay/` 目录，而 Docker 启动时通常会用 `-v` 映射主机上的 SDK 目录，所以 Docker 里面编出来的固件就自动包含了所有你在主机上做好的这些 overlay 预置！

### 1. 启动并进入编译容器

在主机的终端执行：
```bash
# 启动并进入已经配置好的 ubuntu20_dev 容器
docker start -ai ubuntu20_dev
```
*（如果你还没有按照 `02.Docker配置ubuntu20.04环境.txt` 创建容器，请先去创建并安装编译依赖）*

### 2. 在容器内编译并生成镜像

进去之后，终端变成了容器内的 root（比如 `root@xxxxx:/#`），执行以下命令：
```bash
# 进入映射进来的 SDK 根目录（注意：这里是 Docker 里的挂载路径）
cd /BSP/rk3588-linux

# 单独编译 rootfs，这一步会把刚才做好的 ubuntu/overlay 完整打包进 rootfs 里
make ubuntu20

# 编译内核、U-boot，并打包出完整的烧录固件
make
```

### 3. 获取并烧录

编译完成后，你可以直接在主机的 `/home/wzp/BSP/rk3588-linux/output/firmware/` 目录下找到生成的 `update.img`。把它烧录到开发板上，开机即是带有最新 RKNN 和 Miniconda `rknn` 环境的原生固件！

**退出 Docker 容器**：
当你完成编译后，想退回到主机的终端，只需要执行 `exit` 或者按快捷键 `Ctrl + D` 即可。
```bash
# 退出容器环境
exit
```

## 六、实施步骤小结

1. **更新 SDK 内 RKNN**：按第三节执行两条 `cp`。
2. **预置 so + rknn_server**：把 SDK 里已更新的库拷贝到 `ubuntu/overlay/usr/lib` 和 `/usr/bin`。
3. **预置 Miniconda + rknn 环境**：用 qemu+chroot 按文档搭好 aarch64 的 Miniconda 和 rknn 环境，再把装好的环境覆盖进 `overlay/opt/miniconda3`。
4. **验证与打包**：进入稳定的 Docker 容器环境（如 `ubuntu20_dev`）执行 `make ubuntu20` -> `make` 编译出完整的 `update.img`。

完成后，开发板烧录此镜像即默认带可用 RKNN 环境，无需再从零搭环境。

## 七、消除镜像中的 "topeet" 痕迹（改名为 admin）

由于这是迅为（topeet）提供的 SDK，底层内核、设备树（DTS）和基础 Ubuntu 镜像中多处写死了 `topeet`。强行在源码里批量替换极易导致编译失败、找不到文件或无法登录。

我们采用最安全且用户体验最好的方式：**只替换上层的“主机名”并在首次开机时把默认系统用户重命名**。

### 1. 修改系统主机名（Hostname）
修改 SDK 中生成主机名的自动脚本，并且强制覆盖已存在的基础镜像配置。在主机的终端执行（任何目录执行都可以）：
```bash
# 1. 将 SDK 统一配置脚本中的 topeet 替换为 admin
sed -i 's/HOSTNAME="topeet"/HOSTNAME="admin"/g' /home/wzp/BSP/rk3588-linux/device/rockchip/common/scripts/post-hostname.sh

# 2. 强制在 overlay 里写入新的主机名
sudo mkdir -p /home/wzp/BSP/rk3588-linux/ubuntu/overlay/etc
echo "admin" | sudo tee /home/wzp/BSP/rk3588-linux/ubuntu/overlay/etc/hostname
```

### 2. 修改编译菜单 `build.sh` 的顶部网址标题
每次在主机执行 `./build.sh` 弹出的终端图形界面，最上方会显示迅为的域名和描述。把这个也替换掉。
在主机的终端执行：
```bash
sed -i 's|http://www.topeet.com|https://www.my-rk3588.com|g' /home/wzp/BSP/rk3588-linux/device/rockchip/common/scripts/build.sh
sed -i 's|iTOP-RK3588 building script|My-RK3588 building script|g' /home/wzp/BSP/rk3588-linux/device/rockchip/common/scripts/build.sh
```

### 3. 让系统第一次开机自动把 topeet 用户改名为 admin
我们通过 `overlay` 埋入一个自启动脚本（服务）。当板子第一次烧写开机时，它会自动杀掉 `topeet` 进程并用 `usermod` 把用户名、组名及家目录全自动转移给 `admin`，且继承原本的密码和权限。

在主机的终端执行：
```bash
# 1. 创建具体改名脚本
sudo mkdir -p /home/wzp/BSP/rk3588-linux/ubuntu/overlay/usr/local/bin
sudo tee /home/wzp/BSP/rk3588-linux/ubuntu/overlay/usr/local/bin/rename-user.sh << 'EOF'
#!/bin/bash
# 如果已经是 admin 就不执行了
if id "admin" &>/dev/null; then exit 0; fi

# 杀掉可能占用 topeet 的进程
pkill -u topeet
sleep 2

# 把用户 topeet 改名为 admin，并迁移家目录到 /home/admin
usermod -l admin -d /home/admin -m topeet
groupmod -n admin topeet

# 修改相关配置文件里的遗留项
sed -i 's/topeet/admin/g' /etc/sudoers 2>/dev/null || true
sed -i 's/topeet/admin/g' /etc/sudoers.d/* 2>/dev/null || true
sed -i 's/topeet/admin/g' /etc/lightdm/lightdm.conf 2>/dev/null || true
sed -i 's/topeet/admin/g' /etc/gdm3/custom.conf 2>/dev/null || true
EOF

sudo chmod +x /home/wzp/BSP/rk3588-linux/ubuntu/overlay/usr/local/bin/rename-user.sh

# 2. 创建 Systemd 服务，设置为系统启动前的 Oneshot 任务
sudo mkdir -p /home/wzp/BSP/rk3588-linux/ubuntu/overlay/etc/systemd/system
sudo tee /home/wzp/BSP/rk3588-linux/ubuntu/overlay/etc/systemd/system/rename-user.service << 'EOF'
[Unit]
Description=Rename topeet user to admin on first boot
Before=lightdm.service gdm.service sddm.service systemd-user-sessions.service
ConditionPathExists=!/home/admin

[Service]
Type=oneshot
ExecStart=/usr/local/bin/rename-user.sh

[Install]
WantedBy=multi-user.target
EOF

# 3. 启用该服务（软链接到 multi-user.target.wants）
sudo mkdir -p /home/wzp/BSP/rk3588-linux/ubuntu/overlay/etc/systemd/system/multi-user.target.wants
sudo ln -sf /etc/systemd/system/rename-user.service /home/wzp/BSP/rk3588-linux/ubuntu/overlay/etc/systemd/system/multi-user.target.wants/rename-user.service
```
