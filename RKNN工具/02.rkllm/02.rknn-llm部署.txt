02.rknn-llm部署

一、模型转换

注意：迅为官方文档里的DeepSeek-R1-Distill-Qwen-1.5B会在rkllm 1.2.3 版本部署后出现回答无限重复的[PAD151935]的情况
可能原因
模型架构差异：不同架构对量化敏感度不同
激活值分布特性：DeepSeek模型可能有特殊的激活值分布，与rkllm 1.2.3的量化算法不兼容
校准数据适配性：Qwen3-1.7B的校准数据更符合RK3588的量化处理流程

因此以下换成Qwen3-1.7B模型，下方export代码里注意把deepseek的目录名称换成下载的qwen



Qwen3-1.7B 模型下载地址为：https://huggingface.co/Qwen/Qwen3-1.7B，
需要下载该网址全部的文件和模型
然后将上述文件全部拷贝到虚拟机 ubuntu；

然后将 “iTOP-3588 开发板\02_【iTOP-RK3588 开发板】开发资料\13_NPU 使用配套资料
\11_Deepseek 部署测试\01_rkllm-1.1.4\rknn-llm-main\examples\DeepSeek-R1-Distill-Qwen-1.5B_ Demo”路径下的文件拷贝同级目录：

拷贝完成如下，参考目录：
(rknn) wzp@ubuntu:~/RKNN/RKNN_test/qwen3-1.7b$ ls
deploy  export  Qwen3-1.7B


然后在终端中输入以下命令生成量化校准数据，过程如如下所示：
python3 generate_data_quant.py
python3 export_rkllm.py
(或者直接pycharm运行)



二、推理：

修改 /deploy/目录下的 
build-linux.sh 编译脚本，将交叉编译器路径修改为gcc的路径（可以copy之前toolkit2的）:
/usr/local/arm64/gcc-arm-10.3-2021.07-x86_64-aarch64-none-linux-gnu/bin/aarch64-none-linux-gnu

修改 CMakeLists.txt
# set(RKLLM_API_PATH "${CMAKE_SOURCE_DIR}/../../../rkllm-runtime/${CMAKE_SYSTEM_NAME}/librkllm_api")

# TODO: 请将下面的路径修改为你实际 rkllm-runtime/Linux/librkllm_api 的绝对路径
如在/home/wzp/RKNN/rknn-llm-main/rkllm-runtime/Linux/librkllm_api/aarch64/librkllmrt.so
改为（截止到/librkllm_api）
set(RKLLM_API_PATH "/home/wzp/RKNN/rknn-llm-main/rkllm-runtime/Linux/librkllm_api")


保存退出之后，使用“./build-linux.sh”运行脚本（生成build和install文件夹）

编译完成的可执行为存放路径为 install/demo_Linux_aarch64/




开发板运行测试
然后将前面两个小节转换得到的大语言 RKNN 模型和编译得到的可执行文件拷贝到开发板上，在目录中同时存放：xxx.rkllm lib llm_demo

参考指令（以下是替换为Qwen3-1.7B后的）
adb push /home/wzp/RKNN/RKNN_test/qwen3-1.7b/export/Qwen3-1.7B_W8A8_RK3588.rkllm /home/topeet/RKLLM/qwen3-1.7b
adb push /home/wzp/RKNN/RKNN_test/qwen3-1.7b/deploy/install/demo_Linux_aarch64/llm_demo /home/topeet/RKLLM/qwen3-1.7b
adb push /home/wzp/RKNN/RKNN_test/qwen3-1.7b/deploy/install/demo_Linux_aarch64/lib /home/topeet/RKLLM/qwen3-1.7b

最终如下：
(rknn) root@topeet:/home/topeet/RKLLM/qwen3-1.7b# ls
lib  llm_demo  Qwen3-1.7B_W8A8_RK3588.rkllm


由于加载大语言模型会打开很多的文件，默认情况每个进程可以同时打开的文件数是有限
制的，所以需要在终端输入以下命令，允许当前用户在一个会话中打开最多 102400 个文件描述符。
ulimit -HSn 102400
然后使用以下命令，运行可执行程序，并加载 RKLLM 大语言模型，运行成功如所示：
export LD_LIBRARY_PATH=./lib
./llm_demo Qwen3-1.7B_W8A8_RK3588.rkllm 4096 4096



三、显示推理性能的参数

要在RK3588上查看 Token/s (Tokens per Second) 等性能数据，你主要是需要修改 C++ 推理代码（即你提供的第二部分代码）。Python代码主要是用于模型转换（构建）和量化数据的准备，真正的端侧性能主要在C++运行阶段体现。

运行build.sh
然后将编译得到的可执行文件拷贝到开发板上，在目录中同时存放：xxx.rkllm lib llm_demo

参考指令（以下是替换为Qwen3-1.7B后的）
adb shell mkdir -p /home/topeet/RKLLM/qwen3-1.7b
adb push /home/wzp/RKNN/RKNN_test/qwen3-1.7b/deploy/install/demo_Linux_aarch64/* /home/topeet/RKLLM/qwen3-1.7b/
adb push /home/wzp/RKNN/RKNN_test/qwen3-1.7b/deploy/install/demo_Linux_aarch64/lib /home/topeet/RKLLM/qwen3-1.7b/

#开发板串口中：
#在存放刚刚发送的文件的目录下：
ulimit -HSn 102400
#然后使用以下命令，运行可执行程序，并加载 RKLLM 大语言模型，运行成功如所示：
export LD_LIBRARY_PATH=./lib
./llm_demo Qwen3-1.7B_W8A8_RK3588.rkllm 4096 4096



可以把toolkit里的performance.sh放到/home/wzp/RKNN/RKNN_test，然后运行该文件来升频
../performance.sh
